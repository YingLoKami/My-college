# 写代码时踩到的问题

自己反复踩的坑，动手写之前扫一眼。

## 标点符号
- `;` `,` `"` `(` `)` `{` `}` 一律用**英文半角**，中文全角符号是编译错误的高发区
- 分号写成 `；`、引号写成 `“ ”`、逗号写成 `，`，报错常常指向下一行，容易找错地方
- 反斜杠是 `\`（不是 `/`），注意别停在中文输入法

## 分号与格式
- **语句**（statement）结束要加分号 `;`——不是"每一行"都要：`#include <stdio.h>`、`#define AMOUNT 100` 这类预处理指令后面不加，函数的大括号后面也不加
- 大括号 `{ }` 里的代码换行后缩进一个层级（一个 Tab 或四个空格）
  - =={r}原文写"缩进两行"，一般是指缩进一个层级，这里按此理解整理==
- 缩进不影响编译，只影响可读性，但同一个文件里要统一
- 写完一小段就先编译一次，别攒一堆错一起找

## printf
- 忘记 `\n`，后面的输出会挤在同一行
- `%` 占位符的个数要和后面的值一样多，类型也要对得上
- 用 `%d` 去打印 `double` 会输出垃圾值（gcc 一般会给格式警告，别忽略）

## scanf
- `&` 不能省略（`scanf("%d", a);` 是错的，应该是 `&a`）
- 格式串里不要加 `\n`
- 输入内容要和格式串严格对应：格式串里是空格就敲空格，是逗号就敲逗号
- 格式符和变量类型必须匹配：`int` 用 `%d`、`float` 用 `%f`、`double` 用 `%lf`
- `%d` 会自动跳过空格和换行，`%c` 不会跳过（容易读到一个换行符）

## 精度控制
- `%.3f` 是 **printf** 的用法，表示输出时保留小数点后三位：`printf("%.3f\n", 3.14159);` → `3.142`
- `scanf("%.3f", &x)` 是非法格式，读入直接用 `%f` / `%lf`

## 运算
- `5 / 2` 是 `2`，不是 `2.5`；要小数就把一边写成 `5.0`
- `%` 只能用于整数，两侧都必须是整数
- 除数不能为 0
- `(int)3.7` 是截断成 `3`，想要四舍五入得自己写
- `=` 是赋值，判断相等是 `==`，别写混
- `a++` 和 `++a` 单独一行没区别，写进表达式里就不一样（`b = a++` 是先使用再加 1）
- 优先级记不清就加括号，别硬记
- 交换两个变量要用第三方变量中转，顺序写反值就丢了

## const
- `const int N = 10;` 定义时必须给初值，之后再赋值就编译报错
- 常量名全大写，方便和普通变量区分

==🟡不要把赋值，包括复合赋值组合进表达式子！==
a == 6 && b == 1
 如果a == 6已经不成立，那么b == 1就不会进行判断了

## 指针
- ==🔴`int *p, q;` 里只有 `p` 是指针，`q` 是普通 `int`== —— C 里 `*` 修饰的是**变量名**，不是**类型**；`int* p, q;` 和 `int *p, q;` **完全等价**，`int*` 这种东西在 C 里并不存在
- 想定义两个指针就写两个星号：`int *p, *q;`
- 想让星号真的变成类型的一部分，用 `typedef int *int_ptr;`，然后 `int_ptr p, q;` 两个都是指针
- 推荐写法 `int *p;`（星号贴变量名），因为 `int* p, q;` 视觉上会骗人
- ==🔴`a`、`&a[0]`、`&a` 打印出来地址相同，但类型不同==：`a` 和 `&a[0]` 是 `int *`（`+1` 跳 4 字节），`&a` 是 `int (*)[10]`（`+1` 跳 **40** 字节）
- 验证：`sizeof(*a)` = 4（一个 int），`sizeof(*&a)` = 40（整个数组）—— **`%p` 只说"在哪"，`sizeof` 才说"多大"**
- 数组元素保证连续；**独立变量不保证相邻**（顺序可能反、中间可能有对齐填充）
- ==🔴`=` 左边是"目的地"，右边是"来源"== —— 输出参数写 `*pmax = a;`（把 a 送出去），不要写 `a = *pmax;`（把外面读进 a），后者等于把输出当输入用
- ==🔴输出参数必须先写后读== —— `*pmin = a; *pmax = a;` 要放在所有比较之前；不初始化就直接 `if (b > *pmax)`，比的是调用者留下的值
- 形参是"一定被初始化"的局部变量：`f(int *p)` 里的 `p` 自己没定义指向，是调用 `f(&i)` 那一下把 `&i` 赋给它的 —— **一次函数调用 = 一批隐式赋值语句**
- 输出参数会**跨调用残留**：函数没写到的那个值，保留的是上一次调用的结果，容易造成"两次输出一模一样"的假象

## 错题记录

### 错题 1：二维数组找最大值

**目标**：在 2×3 的数组里找最大值及其行列位置。

**我的思路**：双重循环打擂台，`max` 存最大值，`maxi` / `maxj` 存位置。

**错误点**（算法正确，最后一行拿错变量）：

```c
// ... 前面的循环都是对的 ...

printf("Max=%d\n", a[i][j]);   // ❌ 越界
```

**错因**：循环结束后 `i = 2`、`j = 3`。数组合法范围是行 `0..1`、列 `0..2`，`a[2][3]` 已经出界，读到的是垃圾值。

**正确**：

```c
printf("Max=%d\n", max);
```

**教训**：

1. **循环结束后，循环变量停在「超出范围的第一个值」**：`for(i=0;i<2;i++)` 结束后 `i` 是 `2`，不是 `1`。循环外再用 `i` 必须先想清楚它现在是几。
2. **打擂台的结果在 `max` 里，不在数组里**：要找的东西已经存进变量了，别再回数组里翻。
3. 打印行列给用户看时注意 **0 基 vs 1 基**：下标 `[1][2]` 对应人话的「第 2 行第 3 列」，要 `+1`。
4. ==🔴数组的第一个数应该是从0开始数起，而非从1，计算机数数方式和计算思维需要纠正==

### 错题 2：数组排序（打擂台法找最小值放到前面）

**目标**：把 `{5, 2, 9, 1, 7, 3}` 从小到大排好序。

**我的思路**：外层 `j` 是"当前要填的位置"，内层在 `a[j..5]` 里打擂台找最小值，放到 `a[j]`。

---

**错误 1（第二版剩下的唯一错误，也是最核心的）**：

```c
int min = a[j];
for (i = j+1; i < 6; i++) {
    if (a[i] < min) {
        min = a[i];          // ✅ 找最小值没问题
    }
}
a[j] = min;                  // ❌ 这是"抄值",不是"交换"
```

**错因**：`a[j] = min` 只是把最小值**抄**到了前面，`a[j]` 原来那个数**没有被搬到后面去，被直接擦掉了**。结果是最小值出现两次，原来的数丢了。

用两个数就能看清，`{3, 1}`：

```text
j=0: min = a[0] = 3
i=1: a[1]=1 < 3 → min = 1
a[0] = min        → a[0] 变成 1
现在数组是 {1, 1}  ← 3 没了, 1 出现两次
```

**实际输出**：`1 1 1 1 3 3` —— 四个 1、两个 3，7 不见了。

**正确**：先记**位置**（`minIdx`），扫完再**交换**：

```c
for (j = 0; j < 5; j++) {
    int minIdx = j;                 // 假设 a[j] 最小
    for (i = j+1; i < 6; i++) {
        if (a[i] < a[minIdx]) {
            minIdx = i;             // 只记位置, 不动数组
        }
    }
    /* 扫完才交换一次 */
    int t = a[j];
    a[j] = a[minIdx];
    a[minIdx] = t;
}
```

==🔴排好序靠的是"交换",不是"抄值"。抄值会覆盖掉原来的数，产生重复、丢数据。==

---

**错误 2（第一版）**：`for (j = 0; i < 6; j++)` —— 条件用了 `i`，但 `i` 未初始化

**错因**：`int i;` 没赋初值，是垃圾值，拿它当循环条件是未定义行为。更隐蔽的是：即使 `i` 恰好是 0，内层循环结束时 `i` 变成 6，外层判断 `6 < 6` 为假，**外层只跑 1 轮**，后面 5 个位置完全没排。

==🔴for 的三处（初始化 / 条件 / 自增）必须是同一个变量：`for( j = 0; j < 6; j++ )`==

---

**错误 3（第一版）**：`a[i] = min;` 写在了扫描的比较循环里面

**错因**：边走边把 `min` 写回 `a[i]`，**后面还没被比较的元素已经被改掉了**。实际跑一遍 `{5,2,9,1,7,3}` 第一轮结束就变成 `{5,2,2,1,1,1}`，9、7、3 全被抹掉，后面的比较都是在垃圾数据上做的。

正确做法：**扫描阶段只记下标，不碰数组；扫完再交换。**

---

**错误 4（第一版）**：`min = a[0]`，但搜索范围是 `a[j..5]`

**错因**：`j > 0` 之后 `a[0]` 已经不在本轮搜索范围内了。如果 `a[0]` 比 `a[j..5]` 里所有值都小，`min` 就永远不更新，最后拿到一个本轮不该管的数。

正确：初值取本轮范围的第一个元素 `a[j]`（或记下标 `minIdx = j`）。

---
**但这恰恰是问题所在**：`min` 打印出来**永远是"当前数组里的最小值"**，它一直是个合法的数——数组被覆盖坏了，`min` 也跟着坏，但看起来永远正常。所以打印 `min` 根本看不出"数组已经被改坏"这件事。

调试打印应该打**状态，不是结果**：每轮把整个数组打出来（`{1,1,9,1,7,3}`），一眼就能看出 5 和 2 被擦掉了。

---

**教训**：

1. ==🔴排序必须"交换",不能"抄值"== —— `a[j] = min` 是错的，要 `a[j]` 和 `a[minIdx]` 互换。
2. **要记的是"位置"不是"值"** —— 想交换，就必须知道最小元素在哪个下标。`min`（值）换不出东西来，`minIdx`（位置）才能。
3. **交换两个变量要第三方变量** —— `int t = a[j]; a[j] = a[minIdx]; a[minIdx] = t;`，顺序写反值就丢了。
4. ==🔴for 的三处必须是同一个变量== —— `for(j=0; i<6; j++)` 编译器不报错，但逻辑全错。
5. **局部变量不初始化就是垃圾值** —— 别拿它当循环条件、别拿它参与运算。
6. **分两个阶段：先扫、后改** —— 扫描时只记录信息（下标/计数），不要在扫描过程中修改正在被扫描的数据。
7. ==🔴调试打印要打"状态",不是"结果"== —— 打印 `min` 看不出数组被改坏（`min` 永远合法），打印**整个数组**一眼就露馅。最终输出则要放在排序之后。

## 洛谷 P1094 纪念品分组（踩坑汇总）

题目：`w` 是每组价格上限，`n` 件纪念品，每组最多两件，求最少分几组。`n ≤ 30000`。

### 一、我在这题上踩的坑

**1. 以为必须用动态内存分配**
一开始直接问「动态内存分配咋写的」，以为 `n` 是输入的就只能 `malloc`。
实际上 `n ≤ 30000` 编译期就能定，`#define MAXN 30005` + `int a[MAXN];` 放全局就完事。

> ==🔴大数组放全局，小数组放局部，malloc 基本不用==
> 栈默认约 1 MB，`int a[1000000]`（4 MB）写在 `main` 里就会栈溢出；挪到 `main` 外面（全局数据区）就没事。

malloc 申请的完整四步（申请 → 检查 → 使用 → 释放）：
```c
#include <stdlib.h>                      /* malloc / free 都在这里 */

int *a = malloc(n * sizeof(int));        /* ① 申请：要的是字节数，不是元素个数 */

if (a == NULL) {                         /* ② 检查：失败时返回 NULL，也就是地址 0 */
    printf("内存不足\n");
    return 1;
}

for (int i = 0; i < n; i++) {            /* ③ 使用：和普通数组完全一样 */
    scanf("%d", &a[i]);
}

free(a);                                 /* ④ 释放 */
a = NULL;                                /* 立刻置空，防止悬垂指针 */
```

**2. 不理解 `if (a == NULL)` 为什么能判断成败**
`malloc` 只返回一个东西：**地址**。成功给一个非零地址，失败给 `NULL`（就是地址 0）。
操作系统故意保留地址 0 不分配，就是为了让"空指针"有一个可检测的值。
> ==🔴指针是 C 里唯一能表达"没有"的类型== —— `int` 一定是某个数，只能拿 `-1`／`0` 当暗号，而它们本身是合法值会打架；`int *` 可以是 `NULL`，明确表示"我没有指向任何东西"。

## 四、这也解释了 NULL 检查为什么重要

**`p = NULL` 之后 `*p = 0`，就是往地址 0 写数据。** 地址 0 是操作系统保留的，永远不可访问。

**Windows 上会弹“访问冲突 0xC0000005”，Linux 上是 Segmentation fault。**

**而且编译器经常看不出来**（`p` 是运行时才为 NULL 的），所以它不会报错——**你的程序编得过、跑得过一段,然后突然崩在离原因很远的地方。**

**3. 看不懂 `return (x > y) - (x < y);`**
C 里比较运算的结果是 `int`：真为 1，假为 0。所以：

| 情况 | `x>y` | `x<y` | 相减 | qsort 理解 |
|---|---|---|---|---|
| `x > y` | 1 | 0 | **1** | x 排后面 |
| `x < y` | 0 | 1 | **-1** | x 排前面 |
| `x == y` | 0 | 0 | **0** | 相等 |

正好是 qsort 要的三个值。**不能写 `return x - y;`** —— `x = 2e9, y = -2e9` 时 `x - y` 溢出（有符号溢出是未定义行为），排序结果直接乱，而且小数据永远看不出来。

**4. 忘了冒泡排序怎么写，而且这题不能用冒泡**
一句话就能推出来：**相邻两个比，大的往后挪，一轮走完最大的到了末尾。**

```c
for (int i = 0; i < n - 1; i++) {          /* 一共 n-1 轮 */
    for (int j = 0; j < n - 1 - i; j++) {  /* 每轮少比一个 */
        if (a[j] > a[j + 1]) { ... 三条赋值交换 ... }
    }
}
```
内层写成 `j < n` → `a[j+1]` 越界，这是最常见的错法。
> ==🔴"交换"在代码里永远意味着三条赋值== —— `a[j] = min;` 叫**复制**不叫交换，原值被冲掉了（这就是上次排序题那个 bug）。

而且 `n = 30000`，冒泡要 `30000² ÷ 2 ≈ 4.5 亿`次比较，**必超时**；`qsort` 是 O(n log n)，约 45 万次，差 1000 倍。

**5. `qsort` 四个参数搞混**
```c
qsort(a, n, sizeof(a[0]), cmp);
/*    ①    ②      ③        ④      */
```

- ② 是**元素个数** `n`
- ③ 是**每个元素几字节** `sizeof(a[0])`

> ==🔴最常错：把 ② 写成 `sizeof(a)`== —— 那是整个数组的字节数（30005 × 4 = 120020），qsort 会去读 12 万个元素，直接越界。
> 记法：**第 2 个问"几个"，第 3 个问"每个多大"。**

三个附加要求：`#include <stdlib.h>`；cmp 签名必须是 `int cmp(const void *, const void *)`（写成 `int cmp(int*, int*)` 编译不过）；cmp 里必须先强转回原类型再解引用。

**6. `int *i = a[0];` 为什么不行**
因为 `a[0]` 是 `int`（**值**），`int *` 要的是**地址**。
铁律：`a[i] ≡ *(a + i)`，`&a[i] ≡ a + i`。

| 写法 | 类型 | 含义 |
|---|---|---|
| `a + i` / `&a[i]` | `int *` | **地址** |
| `a[i]` / `*(a + i)` | `int` | **值** |

> ==🔴`a[i]` 是"那个数"，`&a[i]` 和 `a+i` 是"那个数在哪"== —— 左边要指针、右边要值，`*` 和 `&` 就是在这两列之间来回换。

顺带分清越界：`a[Num]`（解引用越界）是 UB；`a + Num` 叫**尾后指针**，算地址合法，只是不能解引用。

**7. 双指针循环条件 `i != j` 是个洞**
```c
for (cnt = 0; i != j; j--)   // ❌
```
`i > j`（i 越过 j）的时候 `i != j` **仍然为真**，而 `j--` 写在 for 的更新表达式里——**每一轮必执行**。两件数组走一遍就跑到 `a[2]`、`a[-1]`，读越界内存。

正确：
```c
while (i <= j) {
    if (i == j) { cnt++; break; }   /* 只剩一件，自己一组 */
    if (*i + *j <= Max) i++;        /* 最小的能陪最大的 */
    j--;                            /* 不管配不配，最大的那件都出队 */
    cnt++;
}
```
> ==🔴`i <= j` 而不是 `i != j` —— 允许"越过"，越过就停==
> `j--` 移到循环体末尾，这样"每轮必执行"这件事是**显式的**，你能看见。

**8. `else if (*i + *j > Max)` 是恒真的**
第一个 `if` 不成立，就意味着它成立。直接写 `else`。
> `else if` 等于断言"两件事不会同时发生"——这跟 P5738 里 mx/mn 那个 `else if` 是同一个错。

**11. "a 默认是 a[0]" 这个理解不对**
`a` 在表达式里**退化（decay）**成指向首元素的指针，得到的是**地址** `&a[0]`，不是 `a[0]` 那个值。

> ==🔴不是 `a[0]`，是 `&a[0]`== —— 理解成 `a[0]` 的话，下一条又会写成 `int *i = a[0];`，还是错。

退化的两个**例外**（数组和指针真正分家的地方）：
- `sizeof(a)` → 整个数组字节数（40），不是指针大小
- `&a` → 类型 `int (*)[10]`，`&a + 1` 跳 40 字节，不是 4 字节

### 二、这题的正确写法（备查）

```c
#include <stdio.h>
#include <stdlib.h>

#define MAXN 30005

int a[MAXN];

int cmp(const void *p, const void *q)
{
    int x = *(const int *)p;
    int y = *(const int *)q;
    return (x > y) - (x < y);        /* 不要写 x - y，会溢出 */
}

int main(void)
{
    int w, n, i;
    int cnt = 0, left, right;

    scanf("%d%d", &w, &n);           /* 注意：先 w（上限），后 n（件数） */
    for (i = 0; i < n; i++) {
        scanf("%d", &a[i]);
    }

    qsort(a, n, sizeof(a[0]), cmp);

    left  = 0;
    right = n - 1;
    while (left <= right) {
        if (left == right) {         /* 只剩一件，自己一组 */
            cnt++;
            break;
        }
        if (a[left] + a[right] <= w) {
            left++;                  /* 最便宜的能陪最贵的，配一组 */
            right--;
        } else {
            right--;                 /* 最贵的谁都配不上，自己一组 */
        }
        cnt++;
    }

    printf("%d\n", cnt);
    return 0;
}
```

样例：输入 `100` / `9` / `90 20 20 30 50 60 70 80 90` → 排序后 `20 20 30 50 60 70 80 90 90` → 输出 `6`。

> 最贵的那个，如果能和现在最小的配成一组，那就该配；如果连最小的都配不上，那它跟谁都配不上，只能自己一组。

## qsort 与 cmp

### 一句话分工

> ==🔴cmp 回答「谁在前」，qsort 负责「搬」==

| 角色 | 是谁 | 干什么 |
|---|---|---|
| 数据 | `a` | 躺在内存里，自己不会动 |
| 比较规则 | `cmp` | 被问到时回答「这两个谁该在前」 |
| 排序过程 | `qsort` | 一遍遍问 cmp，一遍遍搬内存 |

替代冒泡排序的是 **`qsort`**（排序过程那一层），不是 `cmp`。
准确说法：**用 `qsort` + `cmp` 替代了手写冒泡**。

### cmp 的契约：只回三种话

| 返回 | qsort 理解为 |
|---|---|
| **负数** | 第一个参数排**前面** |
| **0** | 相等，谁前谁后都行 |
| **正数** | 第一个参数排**后面** |

**只有符号有意义**，−1 还是 −999 效果一样。

### 标准写法（升序）

```c
#include <stdlib.h>                /* qsort 在这里 */

int cmp(const void *a, const void *b)
{
    int x = *(const int *)a;       /* ① 转回 int*  ② 解引用取值 */
    int y = *(const int *)b;
    return (x > y) - (x < y);      /* 得 -1 / 0 / 1，不会溢出 */
}

qsort(a, n, sizeof(a[0]), cmp);    /* 数据、几个、每个多大、判断标准 */
```

### 为什么参数是 `const void *`

| 写法 | 为什么 |
|---|---|
| `void *` | qsort 要能排 `int`、`double`、结构体，它不知道你排什么，用「没有类型」的指针屏蔽掉 |
| `const` | 承诺只读，不改你的数据 |

代价：你拿到的是「不知道是什么」的地址，**第一件事必须自己转回去**。

### 为什么不能写 `return x - y;`

`x = 2e9, y = -2e9` 时 `x - y = 4e9`，超出 `int` 范围 → 溢出成负数 → 排序直接反了。
`(x > y) - (x < y)` 只产生 −1／0／1，**永远不会溢出**。

### 升序 / 降序只差一个符号

```c
return (x > y) - (x < y);   /* 升序：小的在前 */
return (x < y) - (x > y);   /* 降序：两个条件对调 */
```

### 结构体多关键字排序

```c
typedef struct { int id; double score; } Stu;

int cmp(const void *a, const void *b)
{
    const Stu *p = a, *q = b;
    if (p->score < q->score) return -1;
    if (p->score > q->score) return  1;
    return p->id - q->id;      /* 第一关键字相等时，用第二关键字 */
}
```

「多关键字排序」的全部秘密就是最后这一行。

### 证明 cmp 自己不排序

把同一个 cmp 配给自己的冒泡，照样能排：

```c
for (i = 0; i < n - 1; i++)
    for (j = 0; j < n - 1 - i; j++)
        if (cmp(&a[j], &a[j+1]) > 0) {   /* cmp 只回答「要不要换」 */
            int t = a[j];  a[j] = a[j+1];  a[j+1] = t;
        }
```

排好的是那段双重循环。**cmp 和排序是两件独立的事。**

### 三个签名的坑

| 坑 | 后果 |
|---|---|
| 写成 `int cmp(int a, int b)` | qsort 按地址传，你当 int 用 → 崩 |
| 忘了 `#include <stdlib.h>` | 隐式声明，行为未定义 |
| 忘了强转 `(const int *)` | `void *` 不能解引用 → 编译错误 |

## srand 与 rand（播种）

### 先破一个误解

> ==🔴`rand()` 一点都不随机，它是一台确定性机器==

内部就是个公式：

```c
next = (next * 1103515245 + 12345) % 2147483648;
return next;
```

下一个数**完全由上一个数决定**。给定第一个数，后面全部注定。这个「第一个数」就是**种子**。

### 播种到底在做什么

```text
种子 = 数列的起点

srand(1);  →  A B C D E ...
srand(1);  →  A B C D E ...   ← 一模一样
srand(99); →  X Y Z W V ...   ← 换了起点
```

`srand(time(0))` 就是**拿当前秒数当起点**，时间一直在变，看起来才随机。

「播种」这比喻很准：**同样的种子，长出同样的庄稼。**

### 两个函数的分工

| 函数 | 干什么 | 调用几次 |
|---|---|---|
| `srand(seed)` | 设置种子，决定从哪开始 | 整个程序**一次**，放 `main` 开头 |
| `rand()` | 返回 `0 ~ RAND_MAX`（通常 **32767**） | 每要一个数调一次 |

头文件要两个：`<stdlib.h>`（rand、srand）＋ `<time.h>`（time）。

### 三条规矩

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | `srand(time(0));` 在 `main` 开头调**一次** | 起点只需要定一次 |
| 2 | 之后随意 `rand()` | 每次取序列的下一个 |
| 3 | **绝不在同一秒内重复 `srand`** | `time(0)` 一秒才变一次，重复播种 = 回到序列开头 = 出重复的数 |

第 3 条对应的经典 bug：

```c
for (i = 0; i < 10; i++) {
    srand(time(0));          /* ❌ 一秒内播 10 次，种子全是同一个 */
    printf("%d ", rand());   /* 于是打印 10 个一样的数 */
}
```

### 不写 srand 会怎样

C 标准规定：**等价于 `srand(1)`**。
所以每次运行出来的数列**完全一样** —— 看着像随机，其实是死的。

### 播种的第二半用途：可复现

`srand(12345);` 固定种子 → 每次运行序列**完全相同**。

| 场景 | 用法 |
|---|---|
| 复现 bug | 程序偶发崩溃？固定种子跑，崩点每次都一样，好查 |
| 生成世界 | Minecraft 的「地图种子」就是这个原理 |

> ==🔴srand 不是「随机开关」，是「起点的选择器」==
> 要每次不同 → 起点用时间；要每次相同 → 起点用常数。

### 取任意区间的公式

```text
rand() % (区间长度) + 区间起点
区间长度 = 最大值 - 最小值 + 1
```

| 想要 | 写法 |
|---|---|
| 0 ~ 99 | `rand() % 100` |
| 1 ~ 100 | `rand() % 100 + 1` |
| 1 ~ 6（骰子） | `rand() % 6 + 1` |
| 10 ~ 99（真两位数） | `rand() % 90 + 10` |
| 通用 a ~ b | `rand() % (b - a + 1) + a` |

### 和 cmp 的共同点

| | 你提供什么 | 谁干活 |
|---|---|---|
| `cmp` | 一条**比较规则**（谁在前） | qsort 干排序 |
| `srand` | 一个**起点**（从哪开始） | rand 干出数 |

都是「你只交一小块，剩下的别人干」。**这种分工是 C 里第一次出现** —— 以后的函数指针回调、`printf` 可变参数，都是同一个模式。

## my_strcmp（三版迭代）

> ==🔴判断归判断，移动归移动==
> 这一条是从三个版本的失败里熬出来的，比任何单个语法点都值钱。

### 题目

写 `int my_strcmp(const char *a, const char *b)`：`a > b` 返回正数，相等返回 0，`a < b` 返回负数。

### 第 1 版

**关键行**

```c
scanf("%99c", x);
while(*a++ == *b++)
    if((int)*a > (int)*b){ printf("1\n"); }
```

**症状**：卡在输入界面；按完回车输出好几行。

**七个根因**

| # | 问题 | 后果 |
|---|---|---|
| 1 | `%c` 读**恰好 99 个**字符，不跳空白、不补 `'\0'` | 死等凑满 99 个；凑满了也不是合法字符串 |
| 2 | `while` 后面没花括号 | 整条 `if/else if/else` 变成循环体，每前进一步打印一次 |
| 3 | 判断写在循环体里 | 应该在循环**结束后**只做一次 |
| 4 | `*a++` 的自增无条件执行 | 进循环体时指针已经前进，看到的是**下一个**字符 |
| 5 | 没处理 `'\0'` | 两边同时到底时 `'\0' == '\0'` 成立，继续越界读 |
| 6 | `void` 返回 + 内部 `printf` | 函数没有返回值，`main` 拿不到结果 |
| 7 | `(int)*a` 按 signed char 比较 | 值 ≥128 时大小关系反了 |

**修法**：`%99s`；判断移到循环后；`a++; b++;` 独立成句；条件加 `*a != '\0'`；改成 `int` 返回；转 `unsigned char`。

### 第 2 版

**关键行**

```c
while(*a++ == *b++){}
if((int)*a > (int)*b){ ... }
```

**症状**：任何输入都输出 `0`，连 `"Abc"` / `"abd"` 都判成相等。

**根因**：==🔴`*a++` 的自增是无条件的==。比较用的是旧值，但 `+1` 不管比较成不成功都会发生。所以退出循环那一刻，**那个不相同的字符已经被跨过去了**，指针停在后面的字节上；后面恰好都是 `'\0'`，就判成了相等。

**修法**：`a++; b++;` 放进循环体，只在比较通过时前进。等价写法是放进 `for` 的第三个子句 —— 那个子句只在循环体正常结束时执行。

**遗留**：`'\0'` 仍未处理；仍是 `void` + `printf`；仍是 `(int)`。

### 第 3 版

**关键行**

```c
while(*a != '\0' && *a == *b){ a++; b++; }
if((int)*a > (int)*b) return 1;
```

**症状**：ASCII 范围内全对，遇到值 ≥128 的字节方向反。

**根因**：`(int)*a` 在 `char` 为 signed 的平台上把 `0xE4`(228) 读成 `-28`，于是判成「更小」。

**修法**：三处 `(int)` → `(unsigned char)`。

**小噪音**：`main` 里多调了一次 `my_strcmp(x, y);`；`printf("%d", ...)` 漏了 `\n`。

### 三版共同的病灶

`*a++` 和 `while(...) if(...)`，都是把**「移动」和「判断」塞进同一个表达式**。

一旦写在同一处，你就失去了对「什么时候前进」的控制权：

| 版本 | 谁在控制前进 | 结果 |
|---|---|---|
| 1、2 | 条件表达式里的副作用 | 判断失败时也前进 |
| 1 | 判断成了循环体 | 重复执行 N 次 |

> ==🔴判断归判断，移动归移动==

### 最终写法

```c
#include <stdio.h>

int my_strcmp(const char *a, const char *b)
{
    while (*a != '\0' && *a == *b) {
        a++;
        b++;
    }
    if ((unsigned char)*a > (unsigned char)*b) return 1;
    else if ((unsigned char)*a == (unsigned char)*b) return 0;
    else return -1;
}

int main(void)
{
    char x[100], y[100];
    scanf("%99s", x);
    scanf("%99s", y);
    printf("%d\n", my_strcmp(x, y));
    return 0;
}
```

### 六条能搬去任何函数的教训

| # | 教训 |
|---|---|
| 1 | 循环体里要有**明确的**前进语句，不靠条件表达式里的副作用推进 |
| 2 | 判断放在**循环之后**，循环只负责「跳过相同的部分」 |
| 3 | 循环条件同时表达两件事：「不相同就停」+「不能越过 `'\0'`」 |
| 4 | 函数用 `return` 交结果，不要在里面 `printf` |
| 5 | 字符参与比较，先转 `unsigned char` |
| 6 | 读字符串用 `%s` 并带宽度，永远别用 `%c` 读一串 |

### 下次写之前问自己

1. 这个循环**靠什么**前进？（必须有独立语句）
2. 停的条件里，有没有可能**越过边界**？
3. 结果是从 `return` 出去，还是从 `printf` 漏出去？
4. 比较的字节，是有符号还是无符号？

## my_strcpy（六个错误互相掩盖）

> ==🔴拷贝的节奏只能由源决定==
> 源走到 `'\0'` 就停，目的地跟着走同样的步数。

### 症状

输出是 ` b` —— 前面粘了个空格。那个空格就是最硬的证据：==`x2[0]` 从头到尾一个字节都没被写过==。

输入 `abd`，只循环一次、只拷了一个字符，而且拷的是 `'b'` 不是 `'a'`。

### 六个错误（从深到浅）

| # | 错误 | 说明 |
|---|---|---|
| E1 | `b` 同时扮演源和目的地 | `*b != '\0'` 把 `b` 当**源**在数结尾，`*b++ = *a++` 又把它当**目的地**往里写。一个指针两个角色，这是所有乱象的根 |
| E2 | 参数顺序反了 | 标准是 `strcpy(dst, src)`，**第一个是目的地**。要是参数名叫 `dst`/`src` 而不是 `a`/`b`，写下那一刻就暴露了 |
| E3 | 每轮前进两次 | `a++; b++;` 一次，`*b++ = *a++` 又一次。读一个、跳一个 |
| E4 | 先移动，再拷贝 | `a++; b++; *b = *a;` 就算只前进一次，也漏掉了第一个字符 |
| E5 | 循环后多走一格才补 `'\0'` | `b++;` 之后 `b` 已经指着下一个空位，再 `++` 就越过一格，`'\0'` 写在了隔一个洞的位置 |
| E6 | 返回值、`const`、命名 | `void` 要改 `char *`；`src` 要加 `const`；`a`/`b` 该叫 `dst`/`src` |

### 为什么它没崩：假通过

`char x2[100] = " ";` 会把整个数组**清零**（前两个是空格和 `'\0'`，后面 98 个是 0）。

E5 那个多走的洞，位置本来就是 0，看起来一切正常。==🔴把初始化删掉、改成 `char x2[100];` 再跑一次，`b` 后面会冒出一串垃圾==。

这就是自查最有效的一招：**删掉那些「恰好兜住了 bug」的初始化，看错误会不会现形。**

### 一句话病灶

> **拷贝的节奏只能由源决定。** 源走到 `'\0'`，拷贝就结束；目的地跟着走同样的步数。循环里两个指针各走各的，就永远不在同一个位置上。

### 正确骨架

```c
char *my_strcpy(char *dst, const char *src)
{
    char *ret = dst;          /* 记住起点，最后要 return 它 */

    while (*src != '\0') {
        *dst = *src;          /* 先拷 */
        dst++;                /* 再走 */
        src++;
    }
    *dst = '\0';              /* 退出时 src 停在 '\0' 上，它还没被拷 */

    return ret;               /* 返回起点，不是终点 */
}
```

`main` 跟着改：`my_strcpy(x2, x1);`（目的地在前）、`printf("%s\n", x2);`

### 压成一行

```c
while ((*dst++ = *src++) != '\0')
    ;
```

**为什么连 `'\0'` 都不用补**：赋值表达式的值就是被赋的那个字符。最后一次赋值写进去的正是 `'\0'`（值为 0），条件为假、循环退出 —— 而 `'\0'` 已经落到目的地里了。==写和收尾是同一次操作==。

### 和 my_strcmp 那条的关系

| | 病灶 | 教训 |
|---|---|---|
| my_strcmp | 移动和判断塞进同一个表达式 | 判断归判断，移动归移动 |
| my_strcpy | 源和目的地在同一个指针里 | 一个指针只能演一个角色 |

两条是同一个病的两个变种：**让一个变量或一个表达式同时承担两件事**。C 里几乎所有「代码看着对、结果诡异」的 bug，都长这个样子。
