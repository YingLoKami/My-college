# 写代码时踩到的问题

自己反复踩的坑，动手写之前扫一眼。

## 标点符号
- `;` `,` `"` `(` `)` `{` `}` 一律用**英文半角**，中文全角符号是编译错误的高发区
- 分号写成 `；`、引号写成 `“ ”`、逗号写成 `，`，报错常常指向下一行，容易找错地方
- 反斜杠是 `\`（不是 `/`），注意别停在中文输入法

## 分号与格式
- **语句**（statement）结束要加分号 `;`——不是"每一行"都要：`#include <stdio.h>`、`#define AMOUNT 100` 这类预处理指令后面不加，函数的大括号后面也不加
- 大括号 `{ }` 里的代码换行后缩进一个层级（一个 Tab 或四个空格）
  - =={r}原文写"缩进两行"，一般是指缩进一个层级，这里按此理解整理==
- 缩进不影响编译，只影响可读性，但同一个文件里要统一
- 写完一小段就先编译一次，别攒一堆错一起找

## printf
- 忘记 `\n`，后面的输出会挤在同一行
- `%` 占位符的个数要和后面的值一样多，类型也要对得上
- 用 `%d` 去打印 `double` 会输出垃圾值（gcc 一般会给格式警告，别忽略）

## scanf
- `&` 不能省略（`scanf("%d", a);` 是错的，应该是 `&a`）
- 格式串里不要加 `\n`
- 输入内容要和格式串严格对应：格式串里是空格就敲空格，是逗号就敲逗号
- 格式符和变量类型必须匹配：`int` 用 `%d`、`float` 用 `%f`、`double` 用 `%lf`
- `%d` 会自动跳过空格和换行，`%c` 不会跳过（容易读到一个换行符）

## 精度控制
- `%.3f` 是 **printf** 的用法，表示输出时保留小数点后三位：`printf("%.3f\n", 3.14159);` → `3.142`
- `scanf("%.3f", &x)` 是非法格式，读入直接用 `%f` / `%lf`

## 运算
- `5 / 2` 是 `2`，不是 `2.5`；要小数就把一边写成 `5.0`
- `%` 只能用于整数，两侧都必须是整数
- 除数不能为 0
- `(int)3.7` 是截断成 `3`，想要四舍五入得自己写
- `=` 是赋值，判断相等是 `==`，别写混
- `a++` 和 `++a` 单独一行没区别，写进表达式里就不一样（`b = a++` 是先使用再加 1）
- 优先级记不清就加括号，别硬记
- 交换两个变量要用第三方变量中转，顺序写反值就丢了

## const
- `const int N = 10;` 定义时必须给初值，之后再赋值就编译报错
- 常量名全大写，方便和普通变量区分

==🟡不要把赋值，包括复合赋值组合进表达式子！==
a == 6 && b == 1
 如果a == 6已经不成立，那么b == 1就不会进行判断了

关于根号运算符

## 错题记录

### 错题 1：二维数组找最大值

**目标**：在 2×3 的数组里找最大值及其行列位置。

**我的思路**：双重循环打擂台，`max` 存最大值，`maxi` / `maxj` 存位置。

**错误点**（算法正确，最后一行拿错变量）：

```c
// ... 前面的循环都是对的 ...

printf("Max=%d\n", a[i][j]);   // ❌ 越界
```

**错因**：循环结束后 `i = 2`、`j = 3`。数组合法范围是行 `0..1`、列 `0..2`，`a[2][3]` 已经出界，读到的是垃圾值。

**正确**：

```c
printf("Max=%d\n", max);
```

**教训**：

1. **循环结束后，循环变量停在「超出范围的第一个值」**：`for(i=0;i<2;i++)` 结束后 `i` 是 `2`，不是 `1`。循环外再用 `i` 必须先想清楚它现在是几。
2. **打擂台的结果在 `max` 里，不在数组里**：要找的东西已经存进变量了，别再回数组里翻。
3. 打印行列给用户看时注意 **0 基 vs 1 基**：下标 `[1][2]` 对应人话的「第 2 行第 3 列」，要 `+1`。
4. ==🔴数组的第一个数应该是从0开始数起，而非从1，计算机数数方式和计算思维需要纠正==

### 错题 2：数组排序（打擂台法找最小值放到前面）

**目标**：把 `{5, 2, 9, 1, 7, 3}` 从小到大排好序。

**我的思路**：外层 `j` 是"当前要填的位置"，内层在 `a[j..5]` 里打擂台找最小值，放到 `a[j]`。

---

**错误 1（第二版剩下的唯一错误，也是最核心的）**：

```c
int min = a[j];
for (i = j+1; i < 6; i++) {
    if (a[i] < min) {
        min = a[i];          // ✅ 找最小值没问题
    }
}
a[j] = min;                  // ❌ 这是"抄值",不是"交换"
```

**错因**：`a[j] = min` 只是把最小值**抄**到了前面，`a[j]` 原来那个数**没有被搬到后面去，被直接擦掉了**。结果是最小值出现两次，原来的数丢了。

用两个数就能看清，`{3, 1}`：

```text
j=0: min = a[0] = 3
i=1: a[1]=1 < 3 → min = 1
a[0] = min        → a[0] 变成 1
现在数组是 {1, 1}  ← 3 没了, 1 出现两次
```

**实际输出**：`1 1 1 1 3 3` —— 四个 1、两个 3，7 不见了。

**正确**：先记**位置**（`minIdx`），扫完再**交换**：

```c
for (j = 0; j < 5; j++) {
    int minIdx = j;                 // 假设 a[j] 最小
    for (i = j+1; i < 6; i++) {
        if (a[i] < a[minIdx]) {
            minIdx = i;             // 只记位置, 不动数组
        }
    }
    /* 扫完才交换一次 */
    int t = a[j];
    a[j] = a[minIdx];
    a[minIdx] = t;
}
```

==🔴排好序靠的是"交换",不是"抄值"。抄值会覆盖掉原来的数，产生重复、丢数据。==

---

**错误 2（第一版）**：`for (j = 0; i < 6; j++)` —— 条件用了 `i`，但 `i` 未初始化

**错因**：`int i;` 没赋初值，是垃圾值，拿它当循环条件是未定义行为。更隐蔽的是：即使 `i` 恰好是 0，内层循环结束时 `i` 变成 6，外层判断 `6 < 6` 为假，**外层只跑 1 轮**，后面 5 个位置完全没排。

==🔴for 的三处（初始化 / 条件 / 自增）必须是同一个变量：`for( j = 0; j < 6; j++ )`==

---

**错误 3（第一版）**：`a[i] = min;` 写在了扫描的比较循环里面

**错因**：边走边把 `min` 写回 `a[i]`，**后面还没被比较的元素已经被改掉了**。实际跑一遍 `{5,2,9,1,7,3}` 第一轮结束就变成 `{5,2,2,1,1,1}`，9、7、3 全被抹掉，后面的比较都是在垃圾数据上做的。

正确做法：**扫描阶段只记下标，不碰数组；扫完再交换。**

---

**错误 4（第一版）**：`min = a[0]`，但搜索范围是 `a[j..5]`

**错因**：`j > 0` 之后 `a[0]` 已经不在本轮搜索范围内了。如果 `a[0]` 比 `a[j..5]` 里所有值都小，`min` 就永远不更新，最后拿到一个本轮不该管的数。

正确：初值取本轮范围的第一个元素 `a[j]`（或记下标 `minIdx = j`）。

---
**但这恰恰是问题所在**：`min` 打印出来**永远是"当前数组里的最小值"**，它一直是个合法的数——数组被覆盖坏了，`min` 也跟着坏，但看起来永远正常。所以打印 `min` 根本看不出"数组已经被改坏"这件事。

调试打印应该打**状态，不是结果**：每轮把整个数组打出来（`{1,1,9,1,7,3}`），一眼就能看出 5 和 2 被擦掉了。

---

**教训**：

1. ==🔴排序必须"交换",不能"抄值"== —— `a[j] = min` 是错的，要 `a[j]` 和 `a[minIdx]` 互换。
2. **要记的是"位置"不是"值"** —— 想交换，就必须知道最小元素在哪个下标。`min`（值）换不出东西来，`minIdx`（位置）才能。
3. **交换两个变量要第三方变量** —— `int t = a[j]; a[j] = a[minIdx]; a[minIdx] = t;`，顺序写反值就丢了。
4. ==🔴for 的三处必须是同一个变量== —— `for(j=0; i<6; j++)` 编译器不报错，但逻辑全错。
5. **局部变量不初始化就是垃圾值** —— 别拿它当循环条件、别拿它参与运算。
6. **分两个阶段：先扫、后改** —— 扫描时只记录信息（下标/计数），不要在扫描过程中修改正在被扫描的数据。
7. ==🔴调试打印要打"状态",不是"结果"== —— 打印 `min` 看不出数组被改坏（`min` 永远合法），打印**整个数组**一眼就露馅。最终输出则要放在排序之后。
